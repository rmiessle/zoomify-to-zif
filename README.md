# Zoomify Tile Pyramid to ZIF Converter

A Python command-line utility for packaging an existing **Zoomify JPEG tile pyramid** into a single **ZIF (Zoomable Image Format)** file based on BigTIFF.

The converter copies JPEG data **byte-for-byte without recompression**. It was developed to handle Zoomify folders generated by [libvips](https://www.libvips.org/) from large images.

## Requirements

- **Python 3.8 or newer**
- A complete Zoomify image folder containing `ImageProperties.xml` and `TileGroup` directories with `.jpg` or `.jpeg` tiles
- Enough free disk space for the resulting `.zif` file

**No third-party Python packages are required.** libvips is only needed if you want to *create* Zoomify tiles from an original image; it is not required to run this converter.

## Input folder structure

The source should resemble the following:

```text
\path\to\image_zoomify\
├── ImageProperties.xml
├── TileGroup0\
│   ├── 0-0-0.jpg
│   ├── 1-0-0.jpg
│   └── ...
├── TileGroup1\
└── ...
```

The converter discovers tiles by filename across the `TileGroup` directories, checks the pyramid for missing or duplicate tiles, and validates the JPEG dimensions and encoding.

## Usage

### Convert one Zoomify folder

Specify both the input directory and the output file:

```powershell
python zoomify_to_zif.py "\path\to\image_zoomify" "\path\to\image.zif"
```

### Choose the output filename automatically

Omit the output argument:

```powershell
python zoomify_to_zif.py "\path\to\image_zoomify"
```

This creates `\path\to\image_zoomify.zif`.

### Batch-convert multiple images

Place each Zoomify pyramid in a separate subfolder of a parent directory:

```text
\path\to\
├── image1_zoomify\
│   ├── ImageProperties.xml
│   └── TileGroup0\...
├── image2_zoomify\
│   ├── ImageProperties.xml
│   └── TileGroup0\...
└── image3_zoomify\
    ├── ImageProperties.xml
    └── TileGroup0\...
```

Then run:

```powershell
python zoomify_to_zif.py --batch "\path\to\" "\path\to\output"
```

Each **immediate subfolder** containing `ImageProperties.xml` produces a corresponding `.zif` file in `\path\to\output` (for example, `image1_zoomify.zif`). Batch discovery is **not recursive**. If the output directory is omitted, files are saved in the parent input directory.

### Replace an existing output file

By default, the script will not overwrite an existing ZIF. To explicitly replace one, add `--overwrite`:

```powershell
python zoomify_to_zif.py --overwrite "\path\to\image_zoomify" "\path\to\image.zif"
```

### Show command-line help

```powershell
python zoomify_to_zif.py --help
```

On macOS or Linux, use `python3` instead of `python` if needed, and use paths appropriate to your operating system.

## How it works

The script packages the existing JPEGs into a BigTIFF-based ZIF with a layout modeled on a file generated by Zoomify Unlimited:

- Linked image directories (IFDs) from full resolution down to the smallest level
- JPEG tile data stored from smallest resolution to largest
- Individual JPEG tile payloads aligned to 2-byte boundaries
- Tile offset and byte-count indexes stored after the image data
- TIFF metadata and tag types chosen to match the observed Zoomify output

Image pixels are **not resampled or JPEG-recompressed** during packaging.

## Verification and compatibility

A ZIF produced by this version was **successfully opened in Zoomify Unlimited Converter** during testing with an NDPI-derived Zoomify pyramid. Other images, JPEG variants, and viewer implementations have not been comprehensively tested.

After converting, open the ZIF in your target viewer and confirm that the full image displays correctly and that zoom levels and fine details are accessible. Successfully producing a BigTIFF file does not, on its own, guarantee compatibility with every ZIF reader.

## Troubleshooting

- **`python` is not recognized:** Install Python or make sure it is on your system `PATH`.
- **Missing tile error:** Check that the Zoomify export completed and that all expected `.jpg` tiles and `ImageProperties.xml` are present.
- **Duplicate tile error:** Check whether the same level/x/y tile appears more than once across the `TileGroup` folders.
- **Unsupported or inconsistent JPEG tiles:** Confirm the input contains JPEG Zoomify tiles, not PNG or another tile layout.
- **Output already exists:** Choose a new output filename or use `--overwrite` intentionally.
- **The ZIF opens in a TIFF reader but not a Zoomify viewer:** Viewer compatibility can depend on the ZIF layout, so test the result in the application you plan to use.

The converter keeps the source Zoomify folders unchanged and writes the result to a temporary `.part` file before moving it to the requested output filename upon success.
